# Personal IP HTML Design Skill

一套可复用、可改造成任何个人品牌的 HTML 设计 Skill。

它把 Esther 不二设计系统的视觉方法，和真实项目中反复验证的内容架构、图示方式、交互规范、响应式排版、可访问性与发布检查，整理成一套可以直接调用、再品牌化的设计 Skill。使用者可以替换名称、头像、人物形象、色彩、金句、素材与内容领域，建立自己的个人 IP 页面系统。

> **一句话**：把一份中文 AI 主题资料，变成一份讲得清、看得懂、能互动、可公开分享的 HTML 演讲页面。

> **当前版本**：v1.0.0 · 2026-08-04

如果你只是想看最终效果，请先打开 [在线演讲页面](https://6ix-echo.github.io/Six_Echo_Html/)；如果你想让 AI 按同样的方法继续生成页面，再安装并调用本 Skill。

---

## 适合什么时候使用

当你需要以下任务时，可以调用本 Skill：

- 把演讲、课程、文章、作品集或品牌资料做成单页 HTML
- 设计个人主页、个人 IP 海报、活动页、社群介绍页或主题演讲页面
- 将复杂概念、方法论、案例和工作流程转成可视化内容
- 为自己的头像、人物形象、金句与社群入口建立统一的页面系统
- 把个人经验、服务流程、作品和内容资产整理为可复用的品牌组件
- 给已有页面增加翻转卡、标签页、复制按钮和章节导航
- 检查页面的交互、响应式布局、视觉统一性和 GitHub Pages 发布准备

## 不适合什么时候使用

这个 Skill 不是通用的 UI 组件库，也不是只负责“把文字变漂亮”的排版工具。以下任务更适合使用其他专用工具：

- 只需要写一段普通文章或新闻稿
- 只需要完成后端接口、数据库或业务逻辑
- 只需要做数据分析图表而没有演讲叙事需求
- 只需要完成与个人品牌无关的后端、数据或纯技术任务

如果任务同时包含 AI 主题内容、演讲结构和 HTML 交互页面，则优先使用本 Skill。

## 核心方法

```text
原始资料
   ↓
演讲叙事：焦虑 → 认知 → 术语 → 工作系统 → 方法 → 行动
   ↓
视觉结构：时间线 / 关系图 / 对照板 / 案例漫画 / 分类标签
   ↓
交互增强：翻转 / Tab / 复制 / 导航 / 返回顶部
   ↓
QA：内容、视觉、交互、响应式、发布
   ↓
可直接打开和分享的 HTML
```

Skill 的重点不是套用固定模板，而是把设计判断转化为可执行约束：先让内容成体系，再选择能帮助观众理解的视觉结构。

## 内置工作流

| 步骤 | 做什么 | 目的 |
| --- | --- | --- |
| 1 | 判断页面类型、受众、章节数、素材和硬约束 | 不自作主张改变目标 |
| 2 | 读取 Esther 设计系统和对应场景规范 | 先学视觉规矩再动手 |
| 3 | 提炼演讲线和不可遗漏项 | 防止只做漂亮页面而漏内容 |
| 4 | 选择不同的 Section 布局 | 保持长页面节奏 |
| 5 | 用图示解释关系与流程 | 降低术语理解成本 |
| 6 | 加入必要交互与讲者辅助内容 | 页面既能读也能讲 |
| 7 | 做响应式、键盘、打印和资源检查 | 交付可直接使用的页面 |

## 默认内容架构

### 1. 为什么焦虑

用视觉分层、对照和核心观点解释焦虑，不使用夸张或恐吓式表达。

### 2. Agent 与六角色系统

完整呈现：

`LLM → RAG → Agent → Harness → Skill → MCP`

其中 Harness 必须位于 Agent 之后，突出：

> Model 提供能力，Agent 负责行动，Harness 组织可靠执行。

### 3. Harness 露营派对

用“组织一次户外露营烧烤派对”解释 Harness：

1. 接单：目标、人数、地点、时间和边界
2. 翻车：天气、物资、车辆、人员和安全信息没有同步
3. Harness 接管：上下文、状态、工具权限、并行协作和检查点
4. 办成并变好：记录失败、复盘并生成下一次工作记忆

### 4. Prompt 五段式

完整保留：

- Context
- Request
- Output format
- Constraints
- Checkpoint

样例应该以可复制文本呈现，而不是只放截图。

### 5. Skill 体系

从真实重复工作、失败记录和隐性经验出发，沉淀规则、参考、模板、脚本、边界与 Checkpoint，最终形成可复用能力。

Skill 样例采用分类 Tab 展示：

- 内容与视觉
- 研发与工作流
- 知识与研究
- 组织与 AI 员工

条目可以完整保留，但不要全部挤在一屏。

## 视觉基因

- 白色主背景，局部使用淡米色卡片或深色收束带
- 蓝色承担主结构，黄色承担节奏，红色承担强调
- 彩色横条、角标、编号和细线优先于大面积彩色方块
- 中文衬线标题 + 清晰无衬线正文
- 手绘感用于漫画和个人 IP，不使用表情包或通用 AI 插画风
- 人物头像保持用户指定的形象特征、自然比例和视觉风格；本项目示例中的天狗面具只是可替换素材
- 头像金句保持原文，只优化排版位置与层级

默认 CSS 变量：

```css
--paper: #ffffff;
--milk: #f8f4e9;
--ink: #1a1a2e;
--muted: #686b78;
--blue: #2b7fd8;
--yellow: #f4d758;
--red: #ee4862;
```

## 交互规范

- 头像与二维码使用可访问的翻转按钮
- Tab 使用 `aria-selected` 和 `hidden`
- Prompt 使用复制按钮和成功/失败状态
- 顶部导航支持章节锚点，页面提供返回顶部
- 所有操作控件提供清晰的 `:focus-visible`
- 尊重 `prefers-reduced-motion`
- 触控目标不小于 44px
- 所有内容在移动端单列可读，不依赖 hover 才能理解

## Design Skill 拆解

本 Skill 把“审美判断”拆成 AI 可以执行和检查的几层，而不是只给一组颜色：

```text
品牌基因
  ↓ 决定颜色、字体、气质和禁忌
布局 Playground
  ↓ 决定每个 Section 用什么空间关系讲内容
组件库
  ↓ 决定标题、卡片、流程、引用、Tab 和按钮如何落地
场景规范
  ↓ 决定演讲页、教程页、Landing Page 的信息密度
质量检查
  ↓ 决定完成后哪些问题必须返工
```

### 核心设计逻辑

#### 排版：先建立阅读顺序

页面排版遵循“标签 → 标题 → 导语 → 图示 → 正文 → 行动”的层级。标题负责建立记忆点，正文负责解释，图示负责降低理解成本，行动负责让观众知道下一步做什么。

- 中文标题使用高对比衬线字，正文使用清晰无衬线字。
- 英文小标签承担章节识别，不和中文标题争夺主视觉。
- 大标题可以很大，辅助文字要真正小，形成明显字号对比。
- 正文控制阅读宽度，长段落拆成观点、编号或阶段，避免一整面文字墙。
- 所有 Section 都要有自己的节奏，不连续复制同一种卡片网格。

#### 布局 Playground：从空间关系中选方案

布局 Playground 不是装饰展示，而是为内容选择空间语言：

- Hero 双栏不对称：让人物身份和主题建立第一印象。
- Sticky 侧栏：适合章节号与连续解释的深度内容。
- 时间线：适合技术跃迁、历史变化和前后对照。
- 横向流程：适合 Agent Loop、Prompt Flow 和工作步骤。
- 对照板：适合聪明模型与可靠 Harness 的差异。
- 案例漫画：适合把抽象机制翻译成生活场景。
- 分类 Tab：适合完整保留大量 Skill，但控制首屏信息密度。

选择布局时，先问“观众需要理解什么关系”，再决定用几列、几张卡，而不是先决定要使用多少装饰。

#### 组件库全览：让视觉可复用

组件库负责把设计语言落到可重复使用的 HTML/CSS 结构中。常用组件包括：

- `section-head`：英文标签、主标题和导语
- `sticky-layout`：章节侧栏与内容滚动
- `visual-node` / `visual-connector`：概念关系图
- `timeline`：技术跃迁和阶段变化
- `prompt-step` / `prompt-field`：Prompt 五段式
- `harness-comic`：生活化案例漫画
- `view-tabs` / `skill-tabs`：分类浏览和内容切换
- `speaker-note`：低调的讲者辅助提示
- `hero-flip-card`：头像与二维码翻转卡
- `copy-button`：可复制模板和状态反馈

组件应该承担明确的信息功能。不要为了“看起来丰富”而重复嵌套卡片、增加无意义的阴影或堆叠彩色方块。

## 品牌基因速览

### 可替换的个人 IP 基因

本项目以 Six-Echo 的天狗面具头像作为示例，但 Skill 本身不绑定任何人物、行业或 AI 主题。复制使用时，应从自己的素材中提取并固定：

- 品牌名称、英文名与称呼方式
- 头像、人物形象、服饰、道具和身材比例
- 个人金句、价值主张、内容领域与社群入口
- 主色、辅助色、字体气质、图片处理方式和插画风格

这些内容共同构成个人 IP 的视觉识别系统；头像和金句可以保持原文，只调整构图、比例与排版。

### 三色比例

| 颜色 | 色值 | 用途 | 建议比例 |
| --- | --- | --- | --- |
| 蓝 | `#2B7FD8` | 主结构、链接、流程和核心信息 | 60% |
| 黄 | `#F4D758` | 高亮、连接线、节奏和提示 | 30% |
| 红 | `#EE4862` | 标签、CTA、重点和警示 | 10% |

点缀色只做点缀，不把红色或黄色扩展成大面积背景。

### 气质关键词

- 有力量但不压迫
- 有品质但不端着
- 手绘感但不幼稚
- 技术感但不冰冷
- 真实、克制、好奇、可执行
- 一眼能看出是使用者自己的品牌，而不是通用 AI 模板

## 禁忌与注意事项

- 不使用蓝紫渐变、霓虹、玻璃拟态、AI 光效或通用科技背景。
- 不把所有 Section 做成居中标题 + 三张卡片。
- 不用大量彩色方块制造“看起来有设计”的假丰富。
- 不让深色粗边框出现在与全站细线不一致的模块中。
- 不使用表情包、露脸卡通人物或大头小身体的人物比例。
- 不把讲者提示、资料编号和内部制作语言暴露在公开正文中。
- 不省略用户资料中的核心观点、Prompt 样例或 Skill 条目。
- 不让图片过大到压住标题、正文或背景板的留白。
- 不用浏览器默认的引用、列表、表格和按钮样式。

## 质量检查

### 内容检查

- [ ] 目标受众、演讲时长和交付形式明确
- [ ] 主题有完整的“问题 → 认知 → 方法 → 行动”路径
- [ ] LLM、RAG、Agent、Harness、Skill、MCP 分工没有遗漏
- [ ] Harness 案例至少包含目标、失控、组织系统和复盘
- [ ] Prompt 五段式和完整样例可读、可复制
- [ ] Skill 条目按类别展示，没有为了首屏而删除内容

### 视觉检查

- [ ] 品牌名称、素材命名和公开链接已统一，未混入旧品牌信息
- [ ] 背景、色条、标题和卡片层级统一
- [ ] 标题对比度足够，正文不会使用过浅灰色
- [ ] 图片融入内容板，不遮挡文字，不超出可控范围
- [ ] 每个 Section 的布局有变化但仍然属于同一设计系统
- [ ] 手机端没有横向溢出、遮挡或过小文字

### 交互与发布检查

- [ ] 头像翻转可以鼠标、键盘和触控操作
- [ ] Tab 有正确的选中状态和隐藏状态
- [ ] Prompt 复制有成功与失败反馈
- [ ] 所有按钮有焦点样式，动画尊重 reduced motion
- [ ] `index.html`、`assets/` 和相对路径完整
- [ ] GitHub Pages 设置为 `main` / `/(root)`
- [ ] 没有发布隐私资料、测试依赖和本地环境文件

## 怎么用

将 Skill 安装到你的 AI 工作环境后，直接说：

> 使用本 Skill，把这份资料整理成一份可公开分享的 HTML 页面，保留完整内容，并按我的个人 IP 视觉和交互规范实现。

也可以针对单个模块调用：

> 使用 six-echo-ai-talk skill，只重做 Harness 露营派对章节，要求图文可视化、边框统一、照片融入背景板。

### 本地安装

```bash
mkdir -p ~/.codex/skills
unzip six-echo-ai-talk.skill -d ~/.codex/skills/six-echo-ai-talk
```

安装后重新打开 AI 工作环境。如果你的工具支持直接读取 GitHub Skill，也可以使用本目录中的 `SKILL.md` 作为规则源。

### 如何提出更好的请求

为了让输出更接近预期，建议同时说明：

- 页面类型：演讲页、教程页、Landing Page 还是单节解释页
- 受众：技术背景、阅读设备、预计分享时长
- 必须保留的内容：观点、案例、图片、人物信息或原始金句
- 交互要求：翻转卡、Tab、复制、打印或键盘可用性
- 交付方式：本地 HTML、GitHub Pages、Vercel 或其他静态托管

示例：

> 使用 six-echo-ai-talk skill，把这份关于 AI Agent 的草稿做成 15 分钟中文演讲页面。保留所有观点，加入一个露营派对 Harness 案例，白色主背景，移动端可读，Prompt 样例需要支持复制，最后给出 GitHub Pages 发布检查。

## 维护方式

新增规范时，优先判断它属于哪一层：

- 触发条件和总流程 → 修改 `SKILL.md`
- 页面骨架、命名和常见修正 → 修改 `references/project-patterns.md`
- 内容、视觉、交互和发布检查 → 修改 `references/qa-checklist.md`
- 测试输入 → 修改 `evals/evals.json`

修改后应重新检查 YAML frontmatter、资源链接、示例是否可执行，并同步更新版本号和 CHANGELOG。
