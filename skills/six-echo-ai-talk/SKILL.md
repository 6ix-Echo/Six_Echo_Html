# Personal IP HTML Design Skill

这是一套“内容先成体系，再被视觉化，再可被讲出来”的页面生产方法。目标不是堆一页漂亮的卡片，而是让观众沿着一条清晰路径走完：焦虑 → 认知框架 → 术语 → 工作系统 → 可复制方法 → 行动。

## 1. 先判断任务类型

根据用户输入选择一种主模式：

- **主题演讲页**：长页面、章节导航、演讲提示、可打印；默认采用本 Skill 的完整工作流。
- **单节解释页**：只实现一个概念，如 Agent、Harness 或 Prompt，保留同一视觉变量和解释结构。
- **个人 IP / 海报页**：围绕使用者自己的头像、人物形象、金句、色彩与社群入口建立识别系统，交互优先采用头像与二维码翻转卡；六叔的天狗面具只是本项目的示例，不是必选模板。
- **发布页**：优先保留资源相对路径、`index.html`、`.nojekyll` 与 GitHub Pages / Vercel 发布说明。

如果用户给了现有 HTML，应先修改现有结构，不要另起一套页面；先读取其 CSS 变量、组件命名和资源路径，保留已有内容资产。

## 2. 内容架构：用一条演讲线串起来

默认章节顺序如下，可按素材裁剪，但不要打乱因果：

1. **开场问题**：用一句可信、克制的开场建立共同问题，不用夸张的恐吓式话术。
2. **为什么焦虑**：将焦虑拆为可观察的层次、误解和行动差距；用视觉化分层或对照关系，避免一整块文字。
3. **技术跃迁**：把历史变化讲成范式变化，而不是产品年表；强调“先行者不是预测最准的人，而是更早把新能力变成日常动作的人”。
4. **术语系统**：用 LLM、RAG、Agent、Harness、Skill、MCP 六角色解释 AI 应用，不把 Agent 写成“更大的聊天框”。
5. **Harness 生活化案例**：用“组织一次户外露营烧烤派对”讲清楚，从接单、天气变化、采购、人员、车辆与安全，到检查、复盘、下次改进。
6. **Prompt 实践**：展示 Context、Request、Output format、Constraints、Checkpoint 五段式，并提供完整例子与可复制按钮。
7. **搭建 Skill**：讲输入真实工作、沉淀规则/参考/模板/脚本/边界/Checkpoint、输出可复用能力；强调 Skill 的目标是稳定完成特定工作，不是让 AI 更会聊天。
8. **Skill 样例**：按类别展示，不把所有技能挤在一屏；类别切换后再看具体条目。
9. **行动收束**：用 3 个具体动作结束：建立个人工具链、沉淀真实工作方法、用公开作品积累信任。

每个章节都要回答三个问题：观众现在看见什么？为什么重要？听完后能带走什么动作？

## 3. 视觉基线

本 Skill 使用 Six·Echo 设计系统的品牌、排版、布局、组件与质量检查规范。所有规则均以本 Skill 自带内容为准，不依赖作者本机的绝对路径；复制使用时，可替换品牌变量和个人 IP 素材，形成自己的设计版本。

本项目示例的默认变量；复制使用时，应替换为自己的品牌变量：

```css
:root {
  --paper: #ffffff;
  --milk: #f8f4e9;
  --ink: #1a1a2e;
  --muted: #686b78;
  --blue: #2b7fd8;
  --yellow: #f4d758;
  --red: #ee4862;
  --line: rgba(26,26,46,.16);
  --shadow: 0 18px 42px rgba(26,26,46,.08);
}
```

视觉规则：

- 页面主背景优先使用白色；只有明确的深色结尾带或强调段落使用深色背景。不要把所有白色区域泛化成暖色。
- 彩色几何元素优先使用横条、角标、底部色条和小面积圆形，不使用无意义的大量彩色方块。
- 标题使用高对比深色；红、蓝、黄用于标签、编号、强调和关系线，不承担大段正文阅读。
- 版式应有明显节奏：章节标签 → 大标题 → 一句导语 → 图示/内容。避免标题、说明、卡片在同一层级抢视觉焦点。
- 每个 section 选择不同布局：粘性侧栏、时间线、横向角色图、对照板、流程图、分类标签页、案例卡等，避免连续重复卡片。
- 中文正文行高约 1.8，段落宽度控制在 28–42 个汉字；移动端单列，不能出现横向溢出。

### Design Skill 拆解

把设计理解成五层：品牌基因决定“像谁”，布局 Playground 决定“怎么组织空间”，组件库决定“怎么落地”，场景规范决定“适配谁”，质量检查决定“什么必须返工”。

- **排版**：标签 → 标题 → 导语 → 图示 → 正文 → 行动；标题建立记忆，图示降低理解成本，正文解释，行动收束。
- **布局 Playground**：根据关系选择 Hero 双栏、Sticky 侧栏、时间线、横向流程、对照板、案例漫画或分类 Tab；不要先堆卡片再想内容。
- **组件库**：优先复用 `section-head`、`visual-node`、`timeline`、`prompt-field`、`harness-comic`、`skill-tabs`、`speaker-note`、`hero-flip-card` 和 `copy-button`。
- **品牌调性**：有力量但不压迫，有品质但不端着，手绘感但不幼稚，技术感但不冰冷，真实、克制、好奇、可执行。
- **禁忌**：蓝紫渐变、霓虹、玻璃拟态、通用 AI 光效、默认 HTML 样式、彩色方块堆叠、所有 section 同一种卡片网格，以及公开页面中的内部资料编号。

## 4. 个人 IP 视觉与翻转交互

默认保留使用者提供的个人 IP 识别元素：头像、服饰、面具或其他人物特征、自然身材比例、金句与品牌色；不要擅自替换成通用 AI 形象，也不要用表情包风格。素材中的人物规则和金句原文应保持不改，只调整构图与排版。

默认首页头像卡：

- 正面：原头像设计、蓝色底框/边缘细节、金句与“点击头像 → 加入社群”。
- 背面：社群海报与二维码，必须保持可点击、可键盘操作。
- 使用 `button` + `aria-pressed`，通过 `.is-flipped .hero-flip-inner { transform: rotateY(180deg); }` 实现翻转。
- 两面使用 `backface-visibility: hidden`，保持固定宽高比，二维码必须有足够点击区域和备用说明。
- `prefers-reduced-motion: reduce` 时禁用或缩短动画；焦点环必须清晰。

## 5. 核心图示组件

### 5.1 AI 工作系统

用六列或响应式网格表达：

`LLM · 大脑` → 思考、理解与生成

`RAG · 开卷考` → 先查资料，再回答

`Agent · 手脚` → 拆解、调用、执行、检查

`Harness · 组织系统` → 上下文、状态、工具、权限、验证、复盘

`Skill · 做事方法` → 规则、参考、模板、脚本、边界、Checkpoint

`MCP · 万能插板` → 把模型与文件、数据库、服务和外部工具连接起来

Harness 必须放在 Agent 之后，并明确关系：Model 提供能力，Agent 负责行动，Harness 组织可靠执行。

### 5.2 Agent Loop

用“目标 → 规划 → 调用 → 检查 → 交付”的横向流程。每一步写清输入、动作和可验收结果，连接器用箭头或细线，不要让文字压在箭头上。

### 5.3 Harness 露营派对

用真实照片作为序章小图，不要铺满整个背景；照片放在白色/淡蓝色背景板内，并用浅色偏移阴影与细边框融入版面。四格漫画使用统一的天狗面具人物、自然身材比例、手绘蜡笔感和清晰留白：

1. 接单：目标、人数、地点、时间、饮食与安全边界。
2. 翻车：天气突变、设备雨淋、采购遗漏、车辆和人员信息没有同步。
3. Harness 接管外围系统：天气上下文、报名状态、权限工具、并行小组、检查点。
4. 办成并变得更好：记录失败、复盘、形成下一次清单与规则。

再用六个生活角色映射 Harness：目标/上下文、状态/清单、工具/权限、流程/编排、验证/安全、反馈/复盘。卡片底部恢复为蓝/黄/红横条，边框与全站细线系统同步。

### 5.4 Prompt Flow

用五个彩色竖条或横向步骤表达 Context → Request → Output format → Constraints → Checkpoint。完整示例必须可读，不能用截图代替文字；“复制模板”按钮复制纯文本并给出短暂状态反馈。

### 5.5 Skill 系统与类别展示

先用输入真实工作 → Skill 记忆层 → 输出可复用能力的流程图，再用标签页按类别展示技能。默认类别可为：内容与视觉、研发与工作流、知识与研究、组织与 AI 协作。每个类别里完整保留其条目，但不要一次性全部展开。

## 6. 交互与可访问性

- 顶部导航锚点与滚动高亮；移动端导航可折叠或横向滚动。
- `details/summary` 用于演讲提示，提示要低调，不抢正文；不使用“演讲稿/资料 1”这类内部工作字样。
- 标签页使用 `role="tablist"`、`role="tab"`、`aria-selected` 与 `hidden`，键盘可以切换。
- 代码/Prompt 复制按钮使用 `navigator.clipboard`，失败时提供可选文本选择或明确错误反馈。
- 图片有准确中文 `alt`；装饰图使用空 alt；链接和按钮有可理解名称。
- 所有交互状态有 `:focus-visible`；动画尊重 `prefers-reduced-motion`。
- 触控目标至少 44px；页面不依赖 hover 才能理解内容。

## 7. 实现与检查工作流

1. 读取用户素材和现有 HTML，列出内容不可遗漏项与资源引用。
2. 读取 Six·Echo 设计系统对应场景规范，建立 CSS 变量和页面骨架。
3. 先完成内容结构，再完成图示，再加交互，避免用装饰掩盖内容缺口。
4. 运行 `rg` 检查所有资源引用，确保 `assets/` 下文件存在。
5. 用浏览器检查桌面、平板、手机三个宽度；重点看白色背景、标题对比度、照片比例、色条、翻转卡、标签页和长文本是否溢出。
6. 用键盘检查 Tab、Enter、Space、方向键；检查 reduced motion 和打印样式。
7. 若需要发布，复制为 `index.html`，保留 `assets/` 与 `.nojekyll`；GitHub Pages 使用 `main` 分支根目录，Vercel 使用静态目录部署。不要把 tests、node_modules、草稿资料和私密文件一起发布。

## 8. 交付标准

交付应包含：

- 可直接打开的 HTML 文件；
- 所有相对路径资源；
- 交互功能说明（头像翻转、标签切换、复制按钮、返回顶部等）；
- 如已发布，给出公网 URL；如未发布，给出最短发布步骤；
- 页面和交付说明统一使用 Six·Echo 署名，并明确标注使用者自己的品牌素材与授权边界。

不要在最终页面出现“面向几百人的大会演讲稿”“资料 1/3/图示”或内部制作提示等字样，除非用户明确要求。
